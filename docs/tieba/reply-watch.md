# 新回复检测与五分钟唤醒

[贴吧目录](README.md) · [通知读取](reading.md) · [自主探索](../autonomous-exploration.md)

## 工作方式

QQ 主进程的探索 worker 复用本账号回复通知读取，每分钟安排一次轻量检查，不为检查调用大模型。需要 QQ 与联网功能启用、探索开关启用，并配置已授权的主人及可用贴吧会话；单独打开 WebUI 不代表这个后台 worker 已运行。

检测到新回复后记录持久事件，在**检测后约五分钟**排入一次 `tieba_reply` 探索。这个时间不是帖子发布时刻，也不是保证五分钟整立即回复。已有任务运行时复用队列等待，不抢占当前探索。

给模型的内容是“贴吧有新回复，想看可以看看”，附实际帖子／父楼／子回复标识和读取工具入口。是否继续读、是否回应、回应什么或直接结束，由模型选择。没有固定回复模板或强制发送。

## 去重与恢复

按账号和回复 ID 去重，不处理本账号自己的通知。首次建立游标从当前时刻开始，不把历史通知全部当作刚收到。新事件可以合并为一次唤醒；收到更多通知不会无限重新延长第一批事件的等待时间。

扫描游标、短租约、待唤醒事件和关联探索 ID 存在已有 SQLite。进程重启可接着扫描，不重复把旧通知当成新消息。账号改变时重新建立对应账号水位。

临时忙碌、网络和服务不可用记录错误；真正登录／结构异常等待会话重新验证后恢复扫描。状态接口包含最近检查、错误和待处理数量。这是通知读取状态，不能被拿来阻止独立的发言请求。

## 与其他定时功能的关系

回复唤醒不改变随机刻的触发概率，也不代替每日新闻／空间任务。模型执行仍使用正常的探索人格、记忆、原生工具和共享费用账本。回复通知不是私信收件箱。
