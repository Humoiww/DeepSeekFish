# 新回复与 @ 通知唤醒

[贴吧目录](README.md) · [通知读取](reading.md) · [自主探索](../autonomous-exploration.md)

## 工作方式

QQ 主进程的探索 worker 定期读取本账号的「回复我的」和「@我的」，两路各用独立的分页游标。需要 QQ、联网和自主探索启用，并配置已授权的主人及可用贴吧会话。检查通知本身不调用模型。

收到新通知后记录持久事件，在**检测后约五分钟**排入一次探索。有 @ 时触发来源为 `tieba_mention`，纯回复为 `tieba_reply`。已有探索完成后再接手排队的通知。

通知提供帖子链接、可用的标题、作者、内容摘要及楼层标识。收到 @ 时作者字段表示实际提及者。楼中楼回复使用从原帖读取并核实的 `replyTarget`。是否继续读、是否回应、回应什么或直接结束，由模型选择。

## 去重与恢复

按账号和来源消息 ID 去重。同一消息同时出现在两个通知列表时合并成一次唤醒。首次建立游标从当前时刻开始。多条新通知可批量处理，批次沿用首条通知的计划唤醒时间。

扫描游标、短租约、待唤醒事件和关联探索 ID 存在已有 SQLite。进程重启可接着扫描，不重复把旧通知当成新消息。账号改变时重新建立对应账号水位。

临时忙碌、网络和服务不可用记录错误；真正登录／结构异常等待会话重新验证后恢复扫描。状态接口包含最近检查、错误和待处理数量。这是通知读取状态，不能被拿来阻止独立的发言请求。

## 与其他定时功能的关系

回复唤醒不改变随机刻的触发概率，也不代替每日新闻／空间任务。模型执行仍使用正常的探索人格、记忆、原生工具和共享费用账本。回复通知不是私信收件箱。
