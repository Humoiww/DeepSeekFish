# 新主题、普通回复与楼中楼

[贴吧目录](README.md) · [读取 ID](reading.md) · [验证码](verification.md) · [传输层](transport.md)

## 发言权限

`get_tieba_account` 返回服务端确认的身份、实际关注列表及 `posting.mode`。新安装默认 `preview`，仅保存预演；管理员在私有账号配置中明确设为 `live` 后才真实提交。账号必须匹配授权，目标吧必须是当前账号实际关注的吧；其他吧仍只读。

`publish_tieba` 没有 `preview` 或 `mode` 参数，模型不能切换管理员配置。未知字段或动作不匹配会返回具体字段和原因，并标记请求尚未发出。

## 三种动作

| action | 用途 | 必填业务字段 | 不应混入 |
| --- | --- | --- | --- |
| `thread` | 创建新主题 | `forumId`、`title`、`content` | 已有 `threadId/postId/page` |
| `reply` | 在已有主题盖新楼 | `forumId`、`threadId`、`content` | `title/postId` |
| `comment` | 回复父楼或某条子回复 | `forumId`、`threadId`、父楼 `postId`、`content` | 把子回复 ID 当作父楼 |

ID 使用从账号／实际读帖结果取得的数字字符串，不由模型猜测。

`comment` 可选 `subPostId` 指定父楼下的某条子回复；可选 `commentPage` 指明子回复所在页。只回复父楼时不传 `subPostId`。`page` 是主题页码，不是楼中楼页码；父楼核对按 `postId` 直接定位。

## 父子回复的实际绑定

程序读取指定父楼的楼中楼接口，核对 `parentPost.id`、主题和贴吧，再核对目标子回复属于这个父楼及真实作者身份。父楼不在第一页不会再被误判为不存在。

官网路径按父楼 `pid` 打开对应页面，必要时用“展开回复”找到目标子回复。编辑框和发布按钮限定在选中的楼层组件内。子回复的“回复某人”前缀由官网处理；核对出站内容时使用该真实接收者绑定，不把官网自动前缀当作正文篡改。

新主题、回复与申请是不同动作。小吧主申请使用 [专用工具](moderator.md)，不是在主题里回一条申请内容就算完成表单申请。

## 回执与只读复查

| 状态 | 证据 |
| --- | --- |
| 参数／准备失败 | 本地未发出请求，明确记录阶段及原因 |
| `rejected` | 平台明确拒绝，或明确需要验证码 |
| `unknown` / `unconfirmed` | 传输／解析不确定，不能推断未提交 |
| `accepted` | 已被接受，可能已有 PID，但尚未确认公开可见 |
| `confirmed` | 非登录视角读到匹配的 ID、作者、范围、时间和正文 |
| `deleted` | 本账号官方回收站中有同一帖子／回复的系统删除证据 |

使用 `check_tieba_publication({requestId})` 只读复查。只有本人可见、暂未观察到、曾公开可见后未再观察到分别记录；缺少明确删除证据时不冒称系统删帖。HTTP 200、模型说“发好了”和整个探索结束，都不能代替实际回执。

发送前保存意图，拿到回执或 ID 后先持久化，再做读取核对。同一请求重放读取自己的记录；未知送达不自动重发，也不失败后换通道补发。

旧请求被拒或等待验证不阻止新的独立请求。已删除 `publication-needs-human` 跨请求拦截，旧错误只作历史，不冒充新请求的真实返回。
