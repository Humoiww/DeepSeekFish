## 需要区分的证据

| 层次 | 能证明什么 |
| --- | --- |
| 离线协议样本一致 | 请求格式符合核对过的实现 |
| 单独调用传输成功 | 该次请求被平台接受，不代表模型会自主使用 |
| 生成有效 PID | 平台分配了标识，不保证公开可见 |
| 非登录视角读取匹配正文 | 当次内容实际公开可见 |
| 后续只读仍可见 | 在复查时仍存在，不保证永久保留 |
| 真实模型自主选择并调用正式工具 | 模型流程与传输连通，不代表长期稳定 |

HTTP 200、模型总结和探索会话结束都不能单独当作发布成功。一次成功不能推导长期免验证码、免审核或不删帖。

## 复用生产模型

内部 `simulated_owner_signal` 把自然语言指令交给现有探索队列，不伪造 QQ 网络事件或聊天记录。模型使用当前人格、长期知识、历史背景和原生工具，自行选帖、读上下文、写内容、调用正式 Provider。

受控回复验证按该次明确授权记录写入范围，不由操作者提前替模型填帖子和正文，也不以直接调用发布接口代替模型验收。普通人工任务也可通过现有手动入口执行，仍需保留真实触发来源。

## 活动记录与部署版本

私有 trace 保存真正发送的模型请求、工具定义、assistant／tool_call_id 配对、参数、回执、错误和用量。对照实际工具记录计数，不依赖模型事后自述。历史没有保存的错误原因不能凭空补造。

安装器记录基础提交、修改标记及安装文件摘要，保留账号 Profile、SQLite、人格和长期记忆。需要正式验证时，应先部署对应版本；开发副本和 Mock 不得冒充正式服务。

本轮整理只发布实现及说明，不触发额外模型请求、发帖、回帖或申请。详细生产身份、聊天、发言内容、实际请求 ID、截图、凭据及安装记录只留在私有活动记录和运行目录。
