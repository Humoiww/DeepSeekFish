# 贴吧操作队列

贴吧账号的读帖、发言、核对、页面输入及截图共用一个按到达顺序执行的队列。浏览器忙时等待，不再因为其他正常请求正在执行就返回 `TIEBA_BUSY`。状态、队列列表、既有发言记录及保存的截图读取不需要占用浏览器，排队时仍可查看。相同页面的重复截图请求合并；WebUI 看见其他操作等待或执行时暂停自动截图。

打开 WebUI「贴吧账号」，左侧可以看到处理中、等待中和已完成的操作。点选记录，在右侧查看目标、公开发言原文、进入队列和实际开始/结束时间、等待时长及真实回执。已完成只是本地操作结束，界面分别标注预演、已受理待公开确认、公开成功、需要验证、失败、结果不确定和系统删除；既有发言的后续公开核对结果也会反映到列表。上线前的最近发言标注为历史记录，不伪装成新排队或重发。

「已完成」列表和「发言记录」均按时间倒序，每页加载 20 条。分页按钮在列表上方，点击上一页或下一页才会读取对应记录。查看较早的队列页面时，自动刷新只更新等待和处理中状态；点击「刷新」可重读当前页。

队列和发布记录共用账号私有 `actions.sqlite`，不会存密码、验证码、Cookie、截图字节或原始网络响应。最近保留500条非截图完成记录及20条截图记录，未执行请求不按数量丢弃；永久发言回执仍由原发布记录管理。查询入口需要现有主人鉴权，不向模型开放队列设置或宿主机权限。

尚未开始的发言保存其原始目标、原文、请求 ID 和已有授权，服务重启后恢复排队。已经开始的操作中断时记录本地中断，不伪造平台拒绝或自动重新提交；发布是否被接受仍根据原持久回执核对。页面输入和人手点击不跨重启重放。排队中的页面操作绑定原请求和浏览器画面，画面切换后不会把旧点击或旧提交应用到新帖子。

内部调用等待时有无模型消耗的连接心跳；界面提交不会因为单纯排队触发原先的短等待超时。停止服务先停止启动下一项，再等待当前操作结束；发言的去重、关注范围、验证码和结果不明处理继续沿用已有发布模块。这不是每日次数上限或发送冷却，也不改变模型选题、写作与自主调度。

## 执行超时与清理

期限从真正开始执行计算，排队等待不计入：发言及提交原回复240秒，在已打开的发言窗口点击发布或按 Enter 提交也使用这一期限，吧务申请180秒，打开登录或准备官网编辑器120秒，读取与核对90秒，截图、页面输入及退出账号30秒，释放窗口15秒。人工在任务结束后操作已打开的验证窗口，不按排队任务的执行期限倒计时。

超时先保存实际执行环节和当时的提交次数，再中止该任务的网络请求与浏览器指令。清理关闭浏览器，并等待旧任务的异步处理真正结束；只有两者都完成才运行下一项，不使用一个丢弃旧 Promise 的超时竞速放行并发。30秒内不能确认清理完成时，保存超时记录并自动重启现有账号工作进程，未开始的发言重新排队；已开始而结果不明的请求不自动重发，原平台回执和已生成 ID 不被超时状态覆盖。

WebUI 显示执行上限、超时时间、所在环节、清理中/已清理/自动重启恢复，以及独立的原发布回执。队列超时是本地执行诊断，不是贴吧拒绝；后续公开核对也不会抹掉超时记录。浏览器单条指令和网络读取自身的20秒超时也走同一清理流程，界面分别显示具体原因。期限随任务保存，上线前的历史操作不补造执行期限。

## 官网原生提交与回执

点击发布后，官网可能先处理安全校验，再发送真正的发布请求。程序只点击一次，等待实际回执或队列执行期限，不再另设20秒发布等待。每15秒覆盖保存一张最新等待截图及阶段记录；通知、按钮状态、最近40条请求/响应阶段只保留当前提交所需信息，不保存请求体、响应体、请求头、查询参数或凭据。页面通知与平台API回执分开标注，帖子正文不作为平台错误提示。

发布请求放行前同步保存计数；确定本次已结束且计数为0时才标为未提交。请求已经发出但响应丢失则为结果不确定，原计数、失败原因和已生成ID不会被后续异常或只读复查覆盖。已受理、有ID、公开可见和系统删除分别记录。没有新计数的旧记录保持未知，不补造“未发出”的结论。

排队的关闭窗口操作只作用于原窗口；执行前若原窗口已结束或切换，记录为已完成且跳过关闭，并说明原因，不关闭后来的新窗口。其他操作的窗口不匹配使用明确的 `TIEBA_PUBLICATION_WINDOW_CHANGED`，不再被误记为 `INTERNAL_ERROR`。队列异常同时保存脱敏消息、原因和堆栈，WebUI 可展开查看；旧记录没有保存的原始异常不补造。
