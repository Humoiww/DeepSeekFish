# 肥鱼的开发任务

开发入口接收绑定主人发来的 QQ 私聊，也接收主人在已启用的群里 @ 肥鱼或叫她名字发来的直接文字消息。肥鱼沿用自己的人格、记忆和最近聊天来理解需求。她会先在原会话回话，再把委托交给 GPT 小姐。后台用 OneBot 的消息来源确定发送者身份。群内回话确认交接，完整结果和任务详情走主人私聊。转发和引用按聊天资料处理。

可以随口问「GPT 小姐做到哪了」「帮我问她这里为什么这么做」或「让 GPT 小姐停一下」。进度从已有任务记录读取，追问发进正在运行的 Codex 回合。回合已结束时，在原对话继续问。停止会结束当前工作并保留对话。

问题、改动和上线要求都由肥鱼发进同一个对话，Codex 结合上下文和主人原话处理。回合结束后，后台检查实际改动，有可发布的变更就构建和上线。发布结果以开发后台的版本回执为准。

开发服务独立接收 OneBot 消息并核对主人与会话，使用共享 DeepSeek 账本。一次只运行一个开发任务。肥鱼与 GPT 小姐始终使用同一个原生 Codex 对话，Codex 自己管理和压缩上下文。新任务有独立的授权和上线记录，开始时以当前生产版本为基准。开发期间，QQ 聊天、贴吧和生图继续使用各自的处理流程。

本机配置 `FISH_CODEX_NATIVE_SOCKET` 和 `FISH_CODEX_NATIVE_CWD` 后，开发服务连接现有的 Codex CLI daemon，在与桌面相同的项目目录使用原生工作区权限和自动审批。任务的原对话 ID 保持连续。共享目录中的改动按仓库现有流程发布，开发后台核对实际生产版本。

GPT 小姐处理开发任务时使用 GPT‑6.2 Sol，推理级别为极高（`xhigh`）。开发服务在新建和续接会话时核对 Codex 回执，并在每轮提交时携带相同参数。任务记录保存提交的模型、推理级别和回合 ID。

开发回合的次数和耗时只作本地统计。非生图的 Codex 调用没有本地次数、时长或开发返工轮数上限。Codex 额度以本次服务端回执为准，肥鱼按实际来源解释限额和恢复时间。

开发任务可以使用 Codex 原生实时网页搜索。开发命令可以访问 GitHub 网页、API、原始文件和源码归档。命令仍在沙箱内执行，本机和内网目的地由代理拦截，生产数据、Codex 登录目录和其他任务的目录与开发命令隔离。符合审批条件的操作交给 Codex 原生 Auto-review，审查结果记录在开发服务日志中。

GPT 小姐通过 Codex 的 `item/tool/requestUserInput` 提问时，肥鱼用本任务的原话、目标和验收条件回答，把选项或文字按原问题 ID 交回同一回合。问题和答复保存在任务记录中。

肥鱼用平时说话的方式把需求交给 GPT 小姐。GPT 小姐修改并验证候选版本，交付时直接告诉肥鱼改了什么、通过哪个入口或工具使用、实际验证了什么。涉及模拟收发和真实平台的检查，要在交付说明里区分。

后台构建候选版本，核对发布回执里的服务启动结果和安装版本后记录完成。构建失败会把实际输出送回原 Codex 会话。开发任务中，GPT 小姐只读访问开发后台自身的文件。发现候选夹带此类改动时，后台先从生产版本恢复这些文件，再请 GPT 小姐继续处理原需求。

版本切换由独立 systemd 部署器完成。它只应用项目源码、产品资源和生成的 JavaScript，使用固定依赖，保留私有运行数据。新发布目录可由服务账号读取。开发授权、宿主权限、部署器、依赖和服务配置由运维维护。切换前持久化备份与目标版本，启动失败时记录原因、恢复先前文件，清除失败版本占用的 systemd 启动计数并重新启动服务。通知结果不明时核查 QQ 历史，不会重复投递。

开发完成或失败后，肥鱼沿用现有记忆和人格，用普通文字在 QQ 私聊转述。完成时说结果和使用方法，失败时说本次卡点。完整交付说明和原始错误保存在活动记录。

开发委托和通知使用服务商默认输出长度，费用沿用同一个账本。工具返回截断或无效的 JSON 时，不执行这次调用。

开发验证记录可以使用原始字节数、时间和回执编号。发送开发通知前检查可能泄漏的 QQ 号，命中后请肥鱼重新措辞。

## 手工验收策略

1. 用主人私聊发一条小型、明确且容易观察的需求。检查收到任务 ID，以及普通私聊和群聊在开发期间仍可用。
2. 用普通群友发一条相似需求，再让主人只转发或引用该需求。向肥鱼查询开发任务，确认没有新增对应记录。
3. 开发期间查询进度、追问或停止。核对追问进入同一回合，再提交新需求，确认使用同一个会话 ID。开发期间也可在 QQ 正常聊天、处理贴吧。
4. 在一项任务进入开发后，由运维重启肥鱼的 QQ/Web 主服务，确认开发继续。请在安全的维护窗口由运维另外验证开发服务重启与版本回滚。
5. 收到完成消息后，用约定的入口亲自试用，核对报告中的输入、观察结果和版本。验证涉及在线平台的功能时，用你授权的真实账号和数据。
