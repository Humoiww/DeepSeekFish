# 肥鱼的记忆与每日记录

这里保存大肥鱼的人格、知识库、聊天、探索经历和原始调用记录。**没有加密，也不再额外使用 SHA-256 目录或文件名。** 打开日期目录即可阅读。

## 从哪里看

- **[每日记录](daily/README.md)**：按香港日期查看聊天、调用经过和当日实际采集的人格／知识库快照。
- **[当前完整状态](state/)**：保留原始文件名的 JSON、JSONL、图片、GIF、SQLite SQL 和源码。
- **[最近备份时间](latest.json)**：简短的日期与入口信息。

每日目录示例：

```text
daily/2026-11-15/
  README.md          当天阅读入口
  聊天记录.md        按会话、时间及真实发送者排列的聊天
  调用记录.md        工具动作、结果状态、已记录的 token 数
  人格.md            人格分块原文
  知识库.md          长期知识库原文
  好奇心日志.md      已保存的兴趣和经历原文
  persona.json       当次原始人格设置
  chat-originals/    原始聊天 JSONL
  logs/qq/           原始 QQ 调用 JSON，保留原文件名
  logs/exploration/  原始探索调用 JSON
  logs/codex/        原始 Codex 任务 JSON
```

Markdown 只是把真实记录直接排版，**不使用模型总结、改写或补写内容**。原始 JSON / JSONL 也保留。原应用有些日归档文件名本来就是内部 ID，仍按原名保存；普通阅读只需点开 Markdown。

聊天和调用按实际发生的香港日期归档。人格、知识库和好奇心日志快照写明实际采集时间，不把今天的状态冒充成旧日期的状态；旧日期没有单独快照时，只展示已有记录。正在进行的一轮可能暂记为 running，后续备份会保存其完成版本。

## 自动保存

VPS 每天 **香港时间 03:00（UTC+8）** 自动上传一次，不调用 DeepSeek，也不依赖聊天窗口在线。恢复开机后，错过的定时任务补执行一次。

- 每日记录持续保留，源服务器清理旧日志不会删除已归档的每日记录。
- `state/` 是最新完整状态。旧版本由 Git 的正常提交历史保留，按日期选择当时的提交即可恢复当时的状态。
- 不清除 Git 历史，不使用 force push，不设置远端自动过期天数。
- 原图和 GIF 不转换格式。相同内容由 Git 自身存储机制处理，无需另建哈希对象仓库。
- 普通文件直接按原名保存；仅超过 90 MiB 的文件会按 `.part-001` 等顺序分片，避免超过 GitHub 单文件限制。若有分片，`state/backup-info.json` 中记录原路径和分片顺序。
- 数据库先做 SQLite 在线一致快照，再导出可直接查看的 `.sqlite.sql`，保存表结构、数据和版本信息。各数据库分别一致，不表示所有数据库和文件在同一瞬间冻结。
- 上传前先完成本地提交，上传失败时保留已生成的本地提交并记录真实错误。远端确认收到后才更新成功时间和日志备份确认信息。
- 探索详细日志只清理与已确认备份版本相符的文件；未确认的日志继续保留。此规则不限制肥鱼聊天、探索或发言。

本库包含私人对话，必须保持 **Private**。登录 Profile、Cookie、API Key、密码、访问令牌和备份私钥不上传。仓库被改为公开或无法确认访问边界时停止上传，保留本地副本。

## 手动备份与状态

```bash
sudo systemctl start deepseekfish-memory-backup.service
sudo python3 /srv/deepseekfish/app/scripts/backup-state.py status
systemctl list-timers deepseekfish-memory-backup.timer
```

脚本位于 `tools/backup-state.py`。VPS 私钥和状态分别在私有 `runtime/backup/` 与其中的 `status.json`，不属于备份范围。备份使用这个私库专用的 Deploy Key，不改变服务器 SSH 登录或其他平台账号。

## 恢复数据

先克隆本私库。恢复旧日期时，先在克隆目录选择对应日期的 Git 提交；当前版本直接使用当前检出。

```bash
python3 tools/backup-state.py materialize \
  --repository /你的备份仓库目录 \
  --output /一个空的恢复目录
```

程序从具名 `state/` 文件复制数据，将 SQL 重建为 SQLite，并拼接存在的大文件分片。目标必须为空；不覆盖现有生产数据，不启动服务、不发消息、不登录账号。

展开后包含源码和原来的 runtime 布局。新 VPS 按项目文档准备依赖与服务，停止项目进程后安装这些状态文件。普通运行数据归 `deepseekfish`，贴吧回执与策略归 `fishview`；目录0700、数据文件0600。重新配置凭据并登录 QQ／Codex／贴吧，确认账号后再启动服务。已发送消息及已提交申请的回执应一起恢复，避免重复执行。

第一版哈希目录备份仍保留在它原来的 Git 提交中。本次格式调整只移除当前分支上的旧展示目录，没有删除历史。恢复首版时检出首版提交，使用该提交自带的旧脚本。

已经在首次备份前清理的数据无法凭空恢复。长期保留表示程序不主动过期或清除历史；主人宜另留一份独立离线副本。
