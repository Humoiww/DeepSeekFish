# 活动记录与异常排查

WebUI 左侧「活动记录」中，选择失败记录，顶部直接显示失败步骤、模型调用序号、耗时和异常原因链。对应动作内可展开「实际异常 · 原因链与堆栈」；模型动作内可展开「本次实际输入」，按原始 system、user、assistant、tool 顺序查看。工具参数、返回、原生调用 ID、HTTP 请求 ID 和错误响应都保留在同一轮记录中。「下载记录」导出这份凭据已隐藏的记录。

## 记录保证

- 在请求发出前保存实际 messages、工具 schema、模型参数和预算预留 ID；成功和失败使用同一个事件，不重复累加 token。
- API 超时是 `DEEPSEEK_TIMEOUT`，网络错误是 `DEEPSEEK_NETWORK_ERROR`，HTTP 状态保留为 `DEEPSEEK_HTTP_*`；JSON 格式错误单独记录。普通程序异常仍可使用 `INTERNAL_ERROR`，但同时保存原始异常类型、message、stack、cause。
- 已知 token 按接口回执统计，缓存/未缓存拆分不推测。缺少 usage 时显示「未返回」及单独的未确认预留，既不写成已消费，也不算零花费。未通过预算预检的请求标为未发出。
- QQ、随机探索、每日新闻/记忆回顾、WebUI 对话及网页生图规划复用相同的请求追踪。网页失败轮也保存已发生的原生 user/assistant/tool 交互，不能因为请求失败就丢失这些内容。
- JSON 文件原子替换，防止读取半写入文件；诊断字段在序列化前脱敏，避免对整个 JSON 做字符串替换时破坏结构。密钥、Cookie、签名图片链接、图片二进制不入可见记录；详细主机诊断只供主人查看，不进入模型的探索回看。
- 日志不增加模型调用，也不改动模型实际收到的历史、人格、工具选择或预算。模型没有返回响应时，不补造助手回复。

## 旧记录的边界

旧版本将普通异常压成 `INTERNAL_ERROR`，原始异常没有持久化，无法事后凭空恢复。界面会明确说明这一点。若「最后一次实际请求」快照的时间落在该失败轮开始/结束之间，且调用位置、会话一致，可以带来源标注补回真实请求；这不是恢复异常对象，也不能据此确认错误种类。

2026-11-03 的探索 `c64bbcc9-4b10-43c4-9181-4ec5c1b2f4fd`：第一次请求开始于 09:50:36.036 UTC，任务于 09:51:06.059 UTC 结束，相差 30023 ms；没有模型输出和浏览调用。这个时间符合现有 30 秒请求超时，但原始异常已经丢失，因此保留 `INTERNAL_ERROR`，不改写成确定的超时。预留 14514 token 未确认，未重置账本。
