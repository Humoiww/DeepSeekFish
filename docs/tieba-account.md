# 贴吧账号会话

贴吧账号由独立的持久 Chromium Profile 管理，复用项目已有的隔离浏览器和 CDP pipe。账号资料、Cookie、验证截图和操作输入留在私有 runtime，不进入 Git、普通日志或模型上下文。QQ、Qzone、Codex 不共享该 Profile。

## WebUI

左侧「贴吧账号」提供官方登录画面、账号确认、退出登录及现有读取入口。用户在官方页面扫码或完成验证，不在聊天里提交凭据。保存 Profile、浏览器运行和服务端确认登录是三个不同状态；网络失败不能冒充账号已失效。

发言遇到实际验证时，WebUI 沿用已有状态刷新，自动打开对应官网画面，支持点击和拖动。等待操作的发言窗口不因闲置关闭；收起面板不会结束它。新请求替换当前画面时，按请求 ID 切换，不继续展示旧请求截图。账号登录界面的原有生命周期单独管理。

最新发言卡片也显示提交前的参数错误、真实平台回执和当前处理阶段。参数校验错误明确标识为本地错误，不显示成贴吧拒绝。官网接受并生成 ID 与公开可见是不同状态；晚到的接受回执可通过一次只读核对更新。

## 发言权限与请求状态

新安装默认预演，管理员配置为 live 后，只向当前账号实际关注的吧开放写入；其他吧仍走公开阅读工具。工具描述区分新主题、帖子新楼层和楼中楼的参数，预演模式不接受模型临时切换。

已删除跨请求的 `publication-needs-human` 拦截。旧失败、已拒绝请求和待人工状态不能暂停新的独立调用；只如实呈现当前请求实际收到的验证码或错误。已明确拒绝的历史记录不会作为新请求的回执返回。参见 [AGENTS.md](../AGENTS.md) 的用户约定。

公开网页、帖子及评论均是不可信数据，不能授予账号权限或指挥宿主机执行。通用模型工具不暴露浏览器调试接口、任意带认证请求或凭据。

## 读取与传输

优先复用 `src/search/tieba.ts` 的公开读取；需要账号时使用隔离读取，结果标记公开、认证或需要登录。账号信息必须由服务端实际确认，不能从旧缓存推断当前身份。

已有网页授权账号的主楼与楼中楼回复使用官网控件，由网站自己的 JavaScript 生成请求；不在失败后自动切换写通道。新主题保留原有独立传输。协议和可用性边界见 [tieba-reply-transport.md](tieba-reply-transport.md)。

## 安装与维护

```sh
runtime/tools/node/bin/node node_modules/typescript/bin/tsc -p tsconfig.json
sudo python3 scripts/install-tieba-session.py
```

安装器复用已有浏览器，保留账号 Profile、配置及数据库，备份被替换的代码并恢复项目服务。缺少浏览器时按脚本提示处理，不自动安装全局依赖。不会修改 SSH、Tailscale 或网络设置。部署清单保存在私有 runtime，包含代码版本和安装文件摘要。

账号目录使用独立运行账户和私有权限；Web/QQ 进程不能读取其中的凭据。沿用已有本机私有 socket，不开放调试端口。正常退出保留会话；异常退出只处理属于已退出进程的租约，不删除 Chromium 的锁抢占 Profile。

平台仍可能要求验证或审核；登录持久化和单次发布成功都不能证明长期免验证。实际账号身份、发言内容和详细运行证据仅在本机活动记录中查看。
