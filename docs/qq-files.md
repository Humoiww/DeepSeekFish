# QQ 文件和图库发送

QQ 私聊、群聊与自主探索均由模型自行选择工具：

- `send_image(imageId)`：发送任意已授权图库图片。下载图、设定图、头像、空间配图和收到的图片不必先被分类/收藏为表情包。生成图保留原来的送达回执。
- `list_files(offset)`：分页列出当前对话的图库原文件、已完成且属于该对话的 Codex 任务产物。
- `send_file(fileId)`：将目录中的文件作为普通 QQ 附件发送，保留文件名及原字节，支持文档等产物，也支持将图片/GIF作为文件发送。
- `send_meme` 继续提供原有表情包语义。

这些工具不依赖生图开关或文本关键词，不额外调用模型进行意图分类，不改变人格。文件上传本身不新增模型/搜索收费。目录不提供宿主机路径或凭据，也不开放通用 Codex 执行权限。

可信私有 broker 将对话内文件 ID 解析为已经发布的输出或图库原文件；QQ 进程读取原字节，通过 OneBot `send_private_msg` / `send_group_msg` 的 `file` 消息段上传。NapCat 无需访问另一个系统用户的文件目录。该消息段与 `base64://` 输入已按项目使用的 [NapCat v4.18.41 源码](https://github.com/NapNeko/NapCatQQ/blob/v4.18.41/packages/napcat-onebot/api/msg.ts)核对。

每个文件沿用原始媒体的 32 MiB 资源边界，无额外文件扩展名限制；可见任务产物仍由现有产物发布边界控制。链接、跨会话文件和任意宿主路径不进入目录。

上传前持久化意图；同轮重复调用返回已有回执。明确的 QQ 拒绝记为失败，超时、断线、缺少原生 message_id 等记为未确认，跨进程和后续回合均不会盲目重投。已确认的文件可在后续新回合再次主动发送。历史包含确认的文件发送及接收对象，活动记录包含实际工具调用、结果与私有错误诊断。已完成的普通发送回执最多保留 5000 条，未确认回执保留以防重复。
