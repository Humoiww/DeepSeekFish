# 随机刻自主探索

本功能随 QQ 主进程启动一个轻量 worker；默认关闭。它不使用每日新闻或每日空间的任务流程，也不会把后台思考作为用户消息塞入 QQ 对话。

## 使用

部署这版代码并按现有方式启动 QQ 与 WebUI 后，左侧点「自主探索」：

1. 选择 QQ 设置中已经授权的主人私聊账号，打开随机刻开关。
2. 默认每 9～11 分钟检查一次，每次独立以 2.8% 概率醒来。页面显示平均约 4.03 次/天；这是均值，不是每天的任务数。
3. 保存即生效，不必重启 QQ。下次检查重新从保存时刻按新范围抽取。关闭会中断正在运行的随机探索。
4. 「现在醒来一次」用已保存设置排入一项任务，即使总开关关闭也能测试。它会消耗共享额度，模型也可能选择私聊主人。重复点击只返回同一个正在排队/运行的任务。
5. 「停止这次探索」请求取消。不能撤回已提交的发送、模型调用或发布；结果不明的动作会留下回执。

页面展示后台心跳、香港时间的下次检查、最近运行和错误。单独打开 WebUI、未启动 QQ worker 时会明确显示后台尚未连接，排队任务不会假装完成。

最近记录可以跳转到「活动记录 → 自主探索」，查看模型每次输入、缓存/未缓存输入、输出 token，工具参数、结果和实际发送状态。Search/Fetch 的收费沿用现有价格折算，工具结果中单独显示请求数、缓存命中、折算 token 和费用是否确定。不重复把网络折算算成模型输入。没有 provider usage 的失败显示「未确认预留」，不会伪称零成本或退款。网页缓存命中不再扣费。

「好奇心日志」支持搜索、查看全文和来源。模型使用 read_curiosity/write_curiosity 决定记什么，修改带版本号，放弃条目保留旧版本。「她提出的创意」显示 Codex 待审任务。仍通过项目原有本地审批操作；网页、群消息及模型都不能批准任务。原有待审任务 24 小时有效期不变，创意本身也写入可长期查询的兴趣条目。

自主生图、自主公开发空间是两个独立选项，默认关闭。打开生图仍只受现有每日图片额度及实际服务可用性影响；Codex 剩余百分比不是第二重额度。公开发布复用当前 QzonePublisher，当前支持一张不超过 10 MiB 的 PNG。私聊发送不需要开启公开发布。

## 调度与恢复

- SQLite `exploration_schedule` 保存下一次检查时间。每次命中独立抽样，没有主题池、每日计数目标、冷却时间或补触发。
- 重启后若检查时间已过，只检查一次，再从当前时刻抽取下次时间。离线期间不会累积每十分钟一条的任务。
- `exploration_runs` 的部分唯一索引保证最多一个排队/运行任务；事务领取、60 秒租约及随机锁令牌防止多个 worker 重复执行。运行时到来的命中归入现有任务，不排无限队列。
- 心跳每秒续约。过期运行标为 interrupted，不自动从外部副作用前重放。超过一小时、尚未领取的手动任务也不会在长时间离线后突然运行。
- 运行中修改主人、关闭功能、撤销 QQ 私聊权限或点停止，会由 guard/心跳终止后续动作。未完成进度仍可通过 read_exploration 检索，模型之后可自行决定继续。
- 网络错误记入该次记录；worker 继续等待未来随机刻，不以失败为理由立即反复调用付费 API。

## 模型与连续兴趣

复用同一个 BudgetedModel、DeepSeek 原生工具调用及共享 Ledger。每轮 `tool_choice=auto`，没有主题分类、关键词意图判定、固定搜索数量或强制末尾发送。没有固定小轮数；模型随时可以调用 `finish_exploration` 安静结束，包括醒来后立即结束。

API 的 `finish_reason=stop` 只表示这次文本输出结束，不再被当作整场探索完成。无工具文本保留为 assistant 的私下想法，后续附一条 system 运行提示，让模型自行选择继续工具或结束，不伪造用户催促、不匹配话术、不预选工具。连续三次仍只有文字时，以 `EXPLORATION_DECISION_STALLED` 暂停，保留真实消耗与两次继续提示，避免空转；一旦选择工具，此计数归零。这是调用协议故障处理，不是探索行动轮数上限。

初始上下文：当前人格、现有不超过 5000 token 的知识库、主人近期私聊的有界片段、最近五项兴趣的短预览、最近三次同一主人的探索短记。完整资料按模型选择调用 recall_chat/read_curiosity/read_exploration，不永久加载全部历史。群聊只允许读取当前已授权群；后台探索不改变群消息的 @/关键词触发策略。

能力包括公开 Search/Fetch/Browse、现有贴吧/B站适配、原图下载/查看/收藏、图库私聊、QQ 资料/空间、已授权归档、长期知识、兴趣日志与待审创意。可用性继续由原有配置和适配器决定。工具返回失败会交还模型，它可以换路、放弃或结束；没有代码预设的必经步骤。

资源默认：单次最长 60 分钟，可改为 1～1440 分钟；单次模型 token 预算为 0，表示仅遵守共享日额度。也可单独指定单次预算，按既有保守预留检查；未使用的单次预算不是新账本。超过约 24k 文本 token 后，整组移出较旧原生调用/结果，保留近期八组及可检索的原始记录。不会留下孤立 tool 消息。工具内的大网页和旧图片沿用 TurnContext 的按需恢复/预览收起机制。

## 持久化与投递

共享 fish.sqlite 新增调度、运行、外部动作、兴趣条目/版本、提案关联和来源索引表；正常迁移脚本已包含整个数据库，无需另拷绝对路径配置。图片仍进现有 QQMedia/QQImageLibrary，保持原图、动画和来源，沿用 512 MiB 原图存储限额和解码限制。

每次外部发送先持久化 intent。相同内容在同次探索中只执行一次；跨次探索遇到同样的未确认发送也返回原回执，不盲目重发。生成图片使用原有 broker 幂等 ID，图片发送使用原有 sendGeneratedImage 的送达/查证逻辑。只有确认发送的内容以 assistant 身份写入 QQ 聊天记录；私下想法不冒充已发送内容。

详细 trace 位于 runtime/logs/exploration，单次最多 8 MiB，保留最近 90 天且总量不超过 128 MiB。长期运行索引、行动/来源的紧凑事实、好奇心日志及全部修订独立保留；清理详细响应不会删除兴趣经历。read_exploration 支持按关键词检索旧经历，原 trace 过期时返回长期事实索引。没有常驻浏览器或新的外部 Agent 框架。

## 验证

测试入口：`node --test --test-isolation=none dist/tests/exploration.test.js`（先按项目方式构建）。测试涵盖随机分布、零调用检查、设置读写、HTTP/Tailscale 身份、真实 OS 进程竞争、离线/租约恢复、工具自选及转向、原图收藏发送、未知送达去重、安静结束、23 次连续决策、共享收费、权限撤销与 broker 开关、旧经历检索。

当前提交不会自行部署或启用线上功能。运行真实测试时，付费模型/网络走现有共享额度，发送仅进入隔离本地接收器；不进行真实 QQ 发言、公开发布或生图。真实 API 可用性与验收记录另见测试报告。
